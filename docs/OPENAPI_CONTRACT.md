# OpenAPI contract and plugin operations

BSM 4.0 is the source of truth. Curated Python methods return Pydantic models;
`client.rest` exposes typed methods named after operation IDs and `_detailed`
variants containing HTTP status and headers. `async_call_generated` uses the
bundled endpoint serializers and can return raw,
generated typed (`typed=True`), or detailed (`detailed=True`) responses.
`async_call_operation` uses the discovered server contract and returns JSON values,
text, bytes, or `None` for empty responses. The generated and discovered paths use
one connection/authentication/error implementation.

Discover before checking `client.capabilities.has(operation_id)`. Force a refresh
after installing/reloading plugins. Concurrent discovery requests share a refresh;
invalid documents leave the previous snapshot intact. Operation IDs must be unique.
If discovery has established that a generated operation is absent, calls fail with
`NotFoundError` before making an HTTP request. Use discovered operations for routes
whose contract has changed since the installed package was built.

For custom FastAPI plugin routes, use a stable `operation_id` and explicit metadata:

```python
@router.get("/custom/status", operation_id="example_status",
            openapi_extra={"x-bsm-plugin": "example"})
async def status():
    return {"ready": True}
```

The client also recognizes `plugin:example` tags and conventional plugin paths.
Explicit ownership metadata avoids ambiguity for arbitrary routes. Plugins do not
need to install their Python models in the client package.

Runtime JSON bodies and declared parameter values are validated against local
schema references, including nested objects, unions, enums, nullable fields and
constraints. Remote schema references are never fetched. Cookie parameters and
specialized path serialization remain unsupported and should use a purpose-built
adapter. Query form/explode, deepObject, spaceDelimited and pipeDelimited are
supported. Required header names follow HTTP's case-insensitive semantics.

`diff_schemas` reports added, removed and changed operations, including transitive
model and security-scheme changes. `compatibility_report` classifies additions as
additive, removals as breaking, description changes as informational, and other
wire changes conservatively as potentially breaking. It is a review aid, not a
proof of compatibility for arbitrary JSON Schema contracts.

Authentication retries at most once after a 401, releasing the failed response
before requesting a new token. Replayable JSON/form and generated byte bodies can
be retried; multipart files and arbitrary streams are not replayed. Connection
errors, timeouts and 5xx responses do not automatically retry writes. The client
never follows HTTP redirects. Credentials and response bodies are excluded from
transport diagnostics; debug records expose method, status, retry and discovery
counts only. Structured exceptions retain server-provided error metadata.

Use `async with BedrockServerManagerApi(...) as client` to close owned sessions
and generated HTTP clients. Borrowed HTTPX clients and aiohttp WebSocket sessions
remain open. `verify_ssl` and `request_timeout` configure the internally owned
HTTPX client; a supplied `http_client` retains its connection and timeout settings. A URL path represents the
server's reverse-proxy mount; `base_path` selects the API prefix within it.
